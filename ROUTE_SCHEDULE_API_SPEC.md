# Route & Schedule Management - API Specification

## Overview
The Route & Schedule Management module expects the backend to provide RESTful API endpoints for managing routes and schedules. All requests include Bearer token authentication.

## Base URL
```
http://localhost:8081
```

## API Endpoints

### Routes

#### Get All Routes
```
GET /api/routes
```
**Response:**
```json
{
  "data": [
    {
      "routeID": "R1001",
      "title": "City Center Loop",
      "type": "Bus",
      "startPoint": "Central Station",
      "endPoint": "North Terminal",
      "status": "Active"
    }
  ]
}
```

#### Get Route by ID
```
GET /api/routes/{routeID}
```
**Response:**
```json
{
  "data": {
    "routeID": "R1001",
    "title": "City Center Loop",
    "type": "Bus",
    "startPoint": "Central Station",
    "endPoint": "North Terminal",
    "status": "Active"
  }
}
```

#### Create Route
```
POST /api/routes
Content-Type: application/json
Authorization: Bearer {token}
```
**Request Body:**
```json
{
  "title": "City Center Loop",
  "type": "Bus",
  "startPoint": "Central Station",
  "endPoint": "North Terminal",
  "status": "Active"
}
```
**Response:** (201 Created)
```json
{
  "data": {
    "routeID": "R1001",
    "title": "City Center Loop",
    "type": "Bus",
    "startPoint": "Central Station",
    "endPoint": "North Terminal",
    "status": "Active"
  }
}
```

#### Update Route
```
PUT /api/routes/{routeID}
Content-Type: application/json
Authorization: Bearer {token}
```
**Request Body:**
```json
{
  "title": "City Center Loop Updated",
  "type": "Bus",
  "startPoint": "Central Station",
  "endPoint": "South Terminal",
  "status": "Active"
}
```
**Response:** (200 OK)
```json
{
  "data": {
    "routeID": "R1001",
    "title": "City Center Loop Updated",
    "type": "Bus",
    "startPoint": "Central Station",
    "endPoint": "South Terminal",
    "status": "Active"
  }
}
```

#### Delete Route
```
DELETE /api/routes/{routeID}
Authorization: Bearer {token}
```
**Response:** (200 OK)
```json
{
  "message": "Route deleted successfully"
}
```

## Data Models

### Route Entity
```
{
  "routeID": string (generated by backend),
  "title": string (required),
  "type": enum ["Bus", "Metro", "Train"],
  "startPoint": string (required),
  "endPoint": string (required),
  "status": enum ["Active", "Pending", "Inactive"]
}
```

### Schedule Entity
```
{
  "scheduleID": string (generated by backend),
  "routeID": string (reference to Route),
  "date": string (YYYY-MM-DD format),
  "time": string (HH:MM format),
  "status": enum ["Scheduled", "Delayed", "Cancelled", "Completed"]
}
```

## Authentication
All endpoints except GET (public read) require Bearer token authentication:
```
Authorization: Bearer {token}
```

## Error Handling
Expected error responses:
- **401 Unauthorized**: Invalid or missing token
- **404 Not Found**: Resource not found
- **400 Bad Request**: Invalid request data
- **500 Internal Server Error**: Server error

## Frontend Implementation

### Route and Schedule API Module
Location: `src/axios/route_schedule_api.js`

All API functions are async and return axios responses. Wrap calls in try-catch for error handling.

### Main Component
Location: `src/pages/features/routes/RouteScheduleDashboard.jsx`

Displays and manages routes and schedules with a full CRUD interface.

### Sub-components
- `RouteForm.jsx` - Create/update routes
- `RouteList.jsx` - Display routes in a table
- `ScheduleForm.jsx` - Create/update schedules for selected route
- `ScheduleList.jsx` - Display schedules for selected route

## Navigation
- Direct route: `/routes` (requires authentication with 'Routes' permission)
- Dashboard menu: Routes & Schedules section (for authorized users)
